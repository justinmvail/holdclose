# Text-Overflow / Word-Wrap Audit — Holdclose

## Executive summary

Two testing modes fed this audit: an **empirical stress-tester** that actually rendered screens at 320px width with 1.6x-2.0x text scale and long/real data (catching live `RenderFlex` throws), plus three code reviewers reading for latent risk. After dedup, **44 raw findings collapse to 24 distinct issues** (17 real problems + 7 "already-good" reference patterns).

**Headline:** One issue reproduces at *default* text scale on a 320px phone today (Care Circle connect chips — a live bug, not an edge case). Several 4-segment/pill/chip rows throw or hard-clip at large scale, and three cases **truncate clinically meaningful data**: a health-log vitals line drops the last vital, a combination-med chip can overflow, and timeline med names ellipsize. **No medication *name* is silently single-line-clipped** — the med list card and the ICE emergency mirror both handle drug names correctly (this is the one class of text where the app is already careful). The single highest-leverage fix is structural: **PathHeader lives in a non-scrolling `Column` above an `Expanded` body**, so at 2.0x it grows to 966px and starves the list to zero — fix it once in the shared header/scaffold and many screens improve.

Two general remediation patterns cover almost everything: **(1) wrap flexible text in `Flexible`/`Expanded` + `maxLines` + `TextOverflow.ellipsis`** for one-line fields beside fixed chrome; **(2) use `Wrap` (or a scroll view) for chip/segment clusters** instead of a bare `Row`. Use `ellipsis` truncation *only* where the full value lives elsewhere (a detail screen) — **never for vitals, med names on the ICE card, or the last value in a `·`-joined clinical string**.

## Safety-critical truncation (fix first)

These hide clinical data, not just cosmetics.

- **[HIGH] Health-log vitals summary drops the last vital** — `lib/screens/medical/health_log_screen.dart:284-292` (built by `_summaryFor:425-455). The joined string `BP 130/82 · HR 76 · 98.6°F · 110 mg/dL · 152 lb` renders at `maxLines:2 + ellipsis`; at 2.0x a full 5-field line exceeds two lines and **ellipsizes the weight/glucose reading out of existence** — the exact data a caregiver logged for the doctor. **Confirmed in code (line 290-291).** Fix: render each vital as its own `Wrap` chip/segment so all values stay visible and wrap, or raise `maxLines` for the vitals kind specifically. Do not ellipsize a metric away.

- **[HIGH] `_SupplyLine` refill chip can overflow the med card** — `lib/screens/medication/medication_list_screen.dart:505-532`. The needs-attention branch is `Row[ Container(chip 'No refills left'), SizedBox(8), Expanded(Text(reason, ellipsis)) ]`. **Confirmed: the chip `Text` at line 514-521 has no `maxLines` and no `Flexible`** — at ~2.0x the chip `'No refills left'` alone can exceed the card width before the Expanded reason gets any space, so the *chip* overflows. Fix: wrap the chip `Container` in `Flexible(fit: FlexFit.loose)` and give the chip `Text` `maxLines:1 + ellipsis` (or `FittedBox` the chip). Safety note: this is a refill-runway warning — degrade gracefully, don't clip it off the edge.

- **[LOW→note] Combination med names ellipsize on timeline surfaces** — `lib/screens/team/calendar_screen.dart:992-996`, `lib/screens/team/activity_screen.dart:845-861`, and the med-list card head (`medication_list_screen.dart:300`, `maxLines:2`). `'Hydrochlorothiazide/Lisinopril 25mg'` truncates to `'Hydrochlorothiazide/Lisinop…'`, **hiding the second drug in a combination**. Acceptable on summary/timeline surfaces (full name is on the med list) but flag it as a deliberate decision. If reviewers want the second drug visible, allow `maxLines:2` before ellipsizing. Do **not** switch to bare unbounded `Text` (that overflows the fixed Expanded column). The med-list head at `:300` keeps the *name head* visible (safe), and the ICE emergency mirror (`emergency_card_screen.dart:540-578`) wraps unbounded and never ellipsizes a drug name — keep both as-is.

## Empirically-confirmed overflows (rendered, threw `RenderFlex`)

Ordered by severity. These are real, not speculative.

### Navigation / shared header
- **[HIGH] PathHeader starves the list body — Medications header eats the viewport** — `lib/screens/medication/medication_list_screen.dart:139` (outer `Column`), root cause `lib/widgets/path_header.dart`. **Measured: PathHeader renders 966px tall at 2.0x on width 320** (title wrap + breadcrumb `Wrap` one crumb per line + trailing 2 `IconButton`s + 44px profile action). The structure `SafeArea > Column > [PathHeader, Expanded(ListView)]` gives the list 0px and clips the header: **"RenderFlex overflowed by 262 pixels on the bottom"** at 2.0x (12px already at 1.6x), *with list data present*. This structure repeats across appointment_detail, care_summary, find_provider — they escape only by fitting. Fix (systemic): move PathHeader **inside** the scroll region (header as first sliver of a `CustomScrollView`), or cap the breadcrumb+title block height so the list keeps a minimum. **Fix in the shared header/scaffold, not per-screen.**

### Chips / segmented controls (bare `Row`, no wrap)
- **[HIGH] Care Circle connect chips overflow at *default* scale — live bug today** — `lib/screens/team/care_circle_screen.dart:292` (`_ConnectChip` inner `Row`), laid out by the `Wrap` in `_ConnectActions:149`. **Confirmed: the chip's inner `Row(mainAxisSize.min)` at :293 with `Icon+SizedBox+Text` at :298-304 can't shrink** — any chip wider than the Wrap run overflows. **Reproduced at EVERY scale: 25px overflow at scale 1.0 (baseline, no large text needed)**, 176/17/85/130px at 1.6x, 277/51/79/164/220px at 2.0x. These 5 chips are the *only* way to connect a circle. Fix: wrap the label `Text` in `Flexible` with `ellipsis` inside the chip's `Row` (keep the icon visible), or cap the chip container width and let the label ellipsize.
- **[HIGH] find-provider "Show" segmented button (People/Clinics/All) overflows** — `lib/screens/medical/find_provider_screen.dart:234-249`. `SegmentedButton` lays segments at intrinsic width with no ellipsis/wrap fallback; at ~1.8x+ (or once localized to Spanish `Personas/Clínicas/Todos`) the three segments exceed the 40px-margin body width → horizontal overflow. Fix: wrap in a horizontal `SingleChildScrollView`, or replace with a `Wrap` of `ChoiceChip`s, or `FittedBox` each label.
- **[HIGH] Community feed sort selector (Hot/New/Top) overflows** — `lib/screens/community/community_feed_screen.dart:288` (`_SortSelector` `Row` of three `_SortChip`). Bare `Row`, no `Flexible`/`Wrap`. **Reproduced: 38px at 1.6x, 89px at 2.0x.** Spanish would push it even at 1.0x. Fix: replace `Row` with `Wrap(spacing/runSpacing 8)`, or make it a horizontal `SingleChildScrollView`.
- **[LOW] Community post counts row hairline-overflows with 4-digit counts** — `lib/screens/community/community_feed_screen.dart:693` (`_CountsRow`). **5.8px at 2.0x only, with e.g. 1200 votes / 340 comments; clean at 1.6x.** Fix: shrink the `SizedBox(width:20)` gap or `FittedBox(scaleDown)` the row. Low priority.

### Home schedule card
- **[MEDIUM] Schedule card header row (title + "Calendar →") overflows** — `lib/widgets/home/schedule_card.dart:178` (`_Header` `Row`). **41px at 2.0x.** The `Expanded('Schedule')` title wraps fine but the fixed `TextButton('Calendar →')` grows with scale. (The 232px bottom overflow at `:154` in the same test is a fixed-height-card test artifact — on Home the card is in a scroll view — treat only `:178` as real.) Fix: wrap the button's `Text` in `Flexible` with ellipsis, shorten to an icon at large scale, or move it below the title.

## Code-review risks (not independently reproduced, but latent)

### Hub / tile grids
- **[HIGH] HubTile label + sub-label have zero overflow protection** — `lib/widgets/hub_tile.dart:106-108`. **Confirmed: both are bare `Text(label)` / `Text(subLabel)`** — no `maxLines`, `softWrap`, or `overflow`. Each tile is a fixed `itemWidth=(maxWidth-12)/2` column (~166px @360). Used by the Care hub, Care Circle hub (`care_team_hub_screen.dart`), Chat hub, etc. A long unbroken token overflows/clips; a long phrase (Spanish sub-labels like `care_team_hub_screen.dart:52 'to-dos & assignments'`, `:56 "who's on when"` run +25%) balloons tile height and desyncs the two columns. Fix: `softWrap:true` + `maxLines:2` + `ellipsis` on both (label prefers 2 lines before ellipsis as the tile identity; sub-label is non-critical).

At X-Large on a narrow phone with a popular post (4-5 digit counts) the `'Reply'` label + icons exceed width → RenderFlex. Fix: wrap the `Reply` `TextButton.icon` in `Flexible` (or move the cluster into a `Wrap`, or make Reply icon-only at narrow widths) **and** format large counts compactly (`1.2k`).

## What already handles wrapping well (copy these patterns)

- **Medication list card & ICE emergency mirror — the reference for drug names.** `medication_list_screen.dart:296-322` puts the name in `Expanded` with `maxLines:2 + ellipsis` and keeps the trash icon in its own slot (deliberate comment at :293-295) — the critical name head always shows. `emergency_card_screen.dart:540-578` (`_MedicationMirror`) uses `Text.rich` with **no maxLines** so it wraps fully — the ICE card never hides a drug name from a paramedic. Keep the "name gets its own Expanded, icon gets its own slot" rule for future action icons, and keep the ICE mirror unbounded.
- **Emergency Card long-text sections** — `emergency_card_screen.dart` contacts (:585 Expanded), chips (`_ChipList:479` Wrap), insurance (`_LabeledValue:712` Expanded). Tested at 1.6x AND 2.0x with a 37-char name, 42-char condition chip, 49-char carrier — zero overflow. The Wrap-for-chips + Expanded-for-text pattern is the model; a long condition chip wraps *inside* its pill. (Note: the separate 84px fixed label column at `:718` is the one weak spot, listed above.)
- **Community feed post cards** — `community_feed_screen.dart:580-652`: title `maxLines:2+ellipsis`, body `maxLines:3+ellipsis`, author `Expanded + maxLines:1 + ellipsis`. Exactly right for user-generated preview content. **Template for the HubTile and post-detail-header fixes.**
- **Tab bar labels** — `tab_scaffold.dart:237-251`: `maxLines:1, softWrap:false, overflow:ellipsis`, hardcoded `fontSize:11` so labels don't scale with the in-app multiplier — a deliberate, safe clip that keeps the 64px bar height fixed (documented at :234-236).
- **Grouped dose rows & schedule event rows** — `schedule_card.dart:440-452, 547-569`: med/appointment names in `Expanded + maxLines:1 + ellipsis` with the checkbox/chevron **outside** the Expanded, protecting the time prefix.
- **Chat bubbles** — `chat_screen.dart:760-763`: `ConstrainedBox(maxWidth 0.82×screen)` + plain wrapping `Text` (no maxLines) so message bodies grow vertically and never clip — correct for chat, where truncation would hide info.
- **Roster / loved-ones / SegmentedSubnav** — `care_circle_screen.dart:492-499` (`_MemberRow` handle `Expanded+ellipsis`), `loved_ones_screen.dart:206-222` (name+subtitle `Expanded+ellipsis`), `segmented_subnav.dart:139-145` (pill `Expanded+maxLines:1+ellipsis`). - **PathHeader breadcrumb/title horizontal handling** — `path_header.dart:158` (`Wrap`) and `:230` (`Expanded`): no *horizontal* overflow at any scale. The only problem is *vertical* growth (966px), fixed at the hosting layer.

### General remediation patterns
- **One-line field beside fixed chrome (icon/button/chip):** wrap the text in `Flexible`/`Expanded` + `maxLines:1 + TextOverflow.ellipsis`; keep the fixed sibling out of the flex.
- **Chip / segment / filter clusters:** use `Wrap(spacing/runSpacing 8)` or a horizontal `SingleChildScrollView` — never a bare `Row`. `SegmentedButton` has no ellipsis fallback; prefer `ChoiceChip`s in a `Wrap` or a `Dropdown` at the largest scales.
- **`softWrap:false` MUST pair with `overflow:ellipsis`** — otherwise text hard-clips at the box edge (Settings/Calendar bug). If you force single-line, always ellipsize.
- **Multi-line body / message content:** plain wrapping `Text` (no `maxLines`) inside a `ConstrainedBox` or `Column` — let it grow vertically; put the container in a scroll view so it never starves siblings.
- **Truncate with `ellipsis` ONLY where the full value lives elsewhere** (a detail screen). **Never truncate:** vitals values, med names on the ICE card, or the last item in a `·`-joined clinical string. When in doubt, `Wrap` each value so all stay visible.
